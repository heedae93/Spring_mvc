# 📘 학습정리 작성 가이드 (다음 세션용 인수인계 문서)

> **이 문서의 목적**
> 이 폴더의 학습정리 md들은 **일관된 방식과 문체**로 작성되어 있다. 이 문서는 그 방식을 그대로 재현하기 위한
> **작업 지침서**다. 새 세션(이전 대화를 기억 못 하는 상태)에서도 이 문서만 읽으면 **다음 강의 PDF를 동일한 품질·스타일로**
> 정리할 수 있도록 절차·규칙·환경을 전부 적어둔다.
>
> **AI에게**: 사용자가 "다음 PDF 정리하자"고 하면, **먼저 이 문서를 끝까지 읽고** 아래 절차를 그대로 따를 것.

## 1. 이 학습정리는 무엇인가

김영한 **스프링 MVC 1편** 강의 PDF를 장(章)별로 정리한 **강의식 학습 노트**다.
- **대상 독자**: 학습자 본인(복습용). 시험·면접 대비 포인트도 포함.
- **핵심 성격**: PDF를 요약·복사하는 게 아니라, **"내가 이 자료로 남을 가르친다"는 강의 톤**으로 재구성한 것.

## 4. 작업 절차 (반드시 이 순서대로)

### ① PDF에서 텍스트 추출
```bash
cd <스크래치패드 폴더>
pdftotext -layout "/c/Users/hdh89/Desktop/<대상>.pdf" out.txt
```
- `pdftotext`는 Git 환경에 이미 설치돼 있다(`/mingw64/bin/pdftotext`). `poppler`/`pdftoppm`은 없어서 Read 도구의 PDF 렌더링은 안 됨.

> ⚠️ **가장 중요한 함정**: 이 PDF들은 **한글이 추출되지 않는다.** (`Syntax Error: Unknown character collection 'Adobe-Korea1'`)
> 추출 결과물에는 **코드·영문·기호·구조만** 남고 한글 설명은 공백으로 사라진다.
> → 그래서 **PDF 본문 한글에 의존하지 말 것.** 대신 아래 ②③으로 "무엇을 다루는지"를 파악한다.

### ② 예제·구조 매핑 (추출 텍스트에서)
추출된 txt에서 코드 구조로 챕터 내용을 파악한다.
```bash
grep -nE "public (class|interface) [A-Za-z0-9]+|@WebServlet|@Controller|@RequestMapping" out.txt
grep -oE "http://localhost:8080[^ \"\`]*" out.txt | sort -u
```
- 어떤 예제 클래스·URL·애노테이션이 나오는지 목록을 만든다 → 챕터의 뼈대(섹션 순서)를 잡는다.

### ③ **실제 프로젝트 소스를 읽어 정확한 코드 확보** (핵심 원칙)
- PDF 한글이 없으므로, **정확한 코드는 프로젝트 소스가 "진실의 원천(source of truth)"** 이다.
- ②에서 찾은 클래스들을 프로젝트에서 찾아 **Read로 실제 소스를 읽는다.**
  ```bash
  find <프로젝트>/src/main -name "*.java" | sort
  ```
- 코드 예시는 **반드시 실제 소스에서 인용**한다(추출 txt의 코드는 깨졌을 수 있음). 도메인 클래스, JSP, 설정 파일도 함께 확인.

### ④ 강의식으로 재구성해서 md 작성 (아래 5장 문체 규칙 준수)
- PDF를 **복사·요약하지 말 것.** 코드와 구조를 근거로, **강의하듯 새로 서술**한다.
- 사용자 요구 원문: *"거의 그대로 복사하는 느낌으로 하지 말고, 네가 이 자료로 누군가에게 강의한다고 생각하고 작성해줘. 더 설명하고 싶은 부분이 있으면 추가하고."*

### ⑤ 커밋 · 푸시 (사용자가 "push"라고 할 때만)
- 6장 규칙 참고.

## 5. 문체 · 구성 규칙 (기존 문서와 통일)

### 문서 골격
- 맨 위 `# 제목` + **`> 이 문서의 목표`** 블록(목표, 핵심 흐름 요약, 이전 문서 연결).
- 필요하면 **1부(개념) / 2부(실습)** 로 나눔. 섹션은 **번호(`## 1.`, `## 2.` …)**.
- 맨 끝에 **정리 표**(단계·성과 비교) + 필요 시 **부록**.

### 강의 톤 (가장 중요)
- 학습자에게 **말을 거는 구어체**: "자, 여기서부터…", "~해보세요", "헷갈리기 쉬운데…".
- 단순 나열 대신 **"왜 이게 중요한가 / 어디서 헷갈리나 / 실무에선 어떻게 이어지나"** 를 설명.
- **"신입이 밟는 지뢰", "자주 나오는 시험 포인트"** 같은 실전 경험을 덧붙임.

### 연결고리 (문서·섹션 잇기)
- 새 섹션은 가능하면 **`**연결고리**:`** 로 시작해, 앞 섹션/앞 문서와의 관계를 먼저 설명.
- 다른 학습정리 문서를 파일명으로 참조(예: "`서블릿-학습정리.md` 4번(싱글톤)과 연결").

### "문제 → 해결" 흐름
- 특히 v1→v5, 서블릿→JSP→MVC 같은 진화형 주제는 **"이 방식의 고통 → 다음 방식이 그걸 어떻게 해결"** 사슬로 서술.
- 각 단계 끝에 **`> 💬 성과 / 남은 문제`** 를 정리해 다음 단계로 넘어가는 동기를 만든다.

### 스프링 연결 프레이밍
- 밑바닥(서블릿/직접 구현)을 다룰 땐, 마지막에 **"이건 실무 스프링에서 `@애노테이션` 한 줄로 대체된다"** + **대응표**를 넣는다.
- **"그럼 왜 이 고생을 했나?" → "편리함의 정체를 알고 쓰기 위해"** 로 마무리하는 톤.

### 콜아웃(이모지) 관례
| 표기 | 용도 |
|------|------|
| `> ⚠️` | 주의·함정·시험 포인트 |
| `> 💡` | 팁·실무 참고 |
| `> 💬` | 핵심 통찰·한 줄 정리 |
| `> 🔗` | 다른 섹션/문서와의 연결, 복습 문제 |
| `> 📌` | 혼동 포인트 요약 |
| `> 🔥` | "이건 못 해먹겠다" 같은 문제의식 강조 |
| `> 🧩 🗂️ 🌊 📛` | 개념의 정체/구조/비유/이름풀이 등 상황별 |

### 표 작성 규칙 ⚠️
- **표를 인용문(`>`) 안에 넣지 말 것.** GitHub·IntelliJ 등 다수 뷰어에서 표로 렌더링되지 않는다.
- 제목은 `**굵게**`로 쓰고, 표는 인용문 **밖**에 일반 표로 둔다.

### 코드 블록
- 실제 소스에서 인용하되, **주석(`// ←`)으로 핵심 포인트를 짚어** 강의 효과를 낸다. 너무 긴 코드는 핵심만 발췌하고 `// ...` 로 생략.

## 6. 커밋 · 푸시 규칙

- **사용자가 명시적으로 "push/커밋"이라고 할 때만** 커밋·푸시. (평소엔 파일 작성까지만)
- 브랜치: `main`에 직접 작업(사용자의 기존 방식). 원격: `origin`.
- **커밋 메시지: 한글**, 무엇을 추가/보강했는지 요약. 마지막 줄 attribution:
  ```
  Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>
  ```
  (단, 세션마다 안내되는 attribution 지침이 있으면 그걸 우선.)
- **학습정리 md만 커밋**한다. 사용자가 실험으로 바꾼 **소스 코드 변경(.java 등)은 함부로 커밋에 포함하지 말 것** — 발견하면 알리고 제외.
- 커밋 전 `git status`로 의도치 않은 변경이 섞였는지 확인.

## 7. 환경 메모 (Windows / 이 PC 특이사항)

- OS: Windows 11, 셸: PowerShell + Git Bash(둘 다 사용 가능). Bash에서 Windows 경로 인자 문제 나면 `export MSYS_NO_PATHCONV=1`.
- `pdftotext`: `/mingw64/bin/pdftotext` (설치돼 있음). `pdftoppm`(poppler) 없음 → Read의 PDF 렌더 불가.
- Python: Windows Store 스텁이라 `pip`/실행 안 됨(PyMuPDF 설치 시도 무의미).
- JDK: 프로젝트 실행은 IntelliJ가 **Corretto 15**로 구동. `./gradlew`를 Bash에서 직접 돌리면 다른 JDK가 잡혀 **lombok 컴파일 에러**가 날 수 있음(무시하고 IntelliJ 실행을 신뢰).
- 스크래치패드(임시 파일)는 세션별 temp 폴더 사용. 원본 PDF는 바탕화면.

### 알려진 실행 이슈 (참고)
- IntelliJ **Spring Boot 실행 구성**으로 돌릴 때, 새로 추가한 `@WebServlet` 서블릿이 **등록 안 되어 404**가 나는 현상이 있었음.
  코드는 정상(클린 `java` 실행 시 동작 확인). 해결: **앱 완전 정지 → Build → Rebuild Project → 재실행**, 또는 임시 실행 구성 삭제 후 재생성, 필요 시 **File → Invalidate Caches / Restart**.

## 9. 한 줄 요약 (AI가 기억할 핵심 3가지)
1. **PDF 한글은 안 뽑힌다 → 실제 프로젝트 소스가 진실. 소스를 읽고 코드를 인용하라.**
2. **복사하지 말고 강의하라.** 왜/어디서 헷갈리나/스프링과의 연결을 설명하고, 문제→해결 흐름으로.
3. **표는 인용문 밖에. 커밋은 사용자가 요청할 때만, md만, 한글 메시지로.**
